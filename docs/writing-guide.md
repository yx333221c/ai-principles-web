# 内容写作规范（完整版）

> 本文件是 DESIGN.md §14 的展开。所有内容贡献者在动笔前必须读完本文件与 [glossary.md](./glossary.md)。
> 违反「硬性规则」的稿件不进入评审。

## 0. 优先级顺序

当两条规则冲突时，按此顺序取舍：

1. **正确性**（不误导）
2. **可检验**（读者学完能做到 §4 声明的事）
3. **可读**（句子短、结构清晰）
4. **优雅**（修辞、节奏）

---

## 1. 硬性规则（HARD）

| # | 规则 | 检查方式 |
|---|---|---|
| H1 | 每个模块必须包含六段，段名与顺序固定（钩子/直觉/机制/演示/误区/带走） | 结构校验 |
| H2 | 类比必须出现在直觉段，机制必须出现在机制段；**只有类比没有机制的稿子退回** | 人工评审 |
| H3 | 类比必须写明**失效边界**：`这个类比对……不成立` | grep「不成立」 |
| H4 | 数学符号首次出现必须在同屏内给出中文读法与含义 | 人工评审 |
| H5 | 任何数字（超参数、模型规模、benchmark 分数）必须给来源与时间戳 `[YYYY-MM]` | grep `\[\d{4}-\d{2}\]` |
| H6 | 学术有争议的结论必须两派并列，并加 `badge--debate` | 人工评审 |
| H7 | 凡简化处必须显式标 `badge--simplify`，并说明简化了什么 | 人工评审 |
| H8 | 禁止营销词：震撼/颠覆/革命性/史诗级/降维打击/遥遥领先 | grep 违禁词表 |
| H9 | 禁止把厂商自评当作事实陈述 | 人工评审 |
| H10 | 每条「常见误区」≥3 条，且必须写「为何会产生这个误解」 | 结构校验 |

## 2. 语言风格

- **人称**：用「我们」带读者一起推；不用「你应该」「显然」。
- **句长**：正文句均 ≤25 字，单句只讲一件事。长句拆成两步。
- **段落**：一段一个观点，≤5 行；连续两段同构（「XX 是 YY」开头）视为需要改写。
- **术语**：先给名字再给定义。首次出现写「中文（English）」，之后只用中文译名，必要时 `<abbr>` 保留原词。
- **标题**：不用冒号副标题结构（「注意力：让模型学会读取上下文」→ 拆成模块标题 + tagline）。
- **数字给锚点**：「1750 亿参数」不如「1750 亿参数 ≈ 全球每人分到一个英文单词」。
- **不写「不难」**：对读者不难的东西不需要说；对读者难的东西说「不难」是冒犯。
- **不写「众所周知」**：需要论证的东西不许用「众所周知」跳过。

## 3. 公式与数学

- 默认折叠：机制段的推导细节进 `<details class="math--fallback">`，直觉层只给结论与图。
- 每个公式旁必须有**一句自然语言读法**：
  `Attention(Q,K,V) = softmax(QKᵀ/√d)·V` → 「把每个词和所有词比一遍相似度，归一化成权重，再用权重把值加权求和」。
- 不许出现「容易验证」「同理可得」。
- 维度必须写明（`Q: [n × d_k]`），因为读者最常见困惑是「形状对不对得上」。

## 4. 代码与伪码

- 讲解用**伪码优先**，不依赖任何框架 API。
- 真实代码只允许标准库/NumPy，≤20 行，必须可直接运行。
- 变量命名用教学含义（`scores`、`mask`），不用 `x1`、`tmp`。
- 每 3 行代码配 1 行注释说明「为什么」。

## 5. 图解规范

- 每个模块 ≥1 张静态图解（SVG，随主题换色，使用语义令牌，禁止硬编码颜色）。
- 图注必须以「怎么看：」开头，一句话说明阅读路径（从左到右？按颜色？）。
- 图内文字 ≤8 个字/标签；说明放图注，不塞进图里。
- 一张图只讲一件事；要讲两件就画两张，或用 A/B 面板。
- `<svg>` 必须含 `<title>`、`<desc>`、`role="img"`、`aria-label`。

## 6. Demo 文案规范

每个 demo 的说明必须回答三件事（缺一不可）：

1. **你能改什么**：参数名 + 合法区间 + 物理含义（`temperature ∈ [0, 2]`，0 = 贪心解码）。
2. **拨动它，你会观察到什么规律**：给出可预期的观察结论。
3. **这个规律对应机制段的哪一步**：双向锚回文字。

不许把 demo 写成「试试看！」——没有预测的交互只是玩具。

## 7. 引用与文献

- 关键论断必须有出处：arXiv DOI、官方博客、或教材页码。
- 格式：`来源名（年份）[YYYY-MM]` + 链接；链接必须带 `rel="noopener noreferrer"`。
- 每个模块末尾给「延伸阅读」2 条，标注难度（入门/进阶/原始论文）。

## 8. 时效维护

- 涉及具体模型版本、参数、榜单排名的句子一律带 `[YYYY-MM]` 时间戳。
- `modules.json` 的 `status` 字段是巡检依据：`published` 超过 12 个月未复核 → 降级为 `reviewed` 并在页面显示「可能过时」。
- 写「原理」而非「现状」：把随版本变化的内容压进 `<details>` 的「当前实现」小节。
